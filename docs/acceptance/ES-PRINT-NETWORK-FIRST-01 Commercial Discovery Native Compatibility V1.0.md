Five actual bundled-Electron reads took 1.872–2.178 seconds each. A /24 required 33 fresh metadata processes within a 45-second discovery deadline.

Windows automatically adjusts interface metrics with link speed; this is not itself proof of a new network. [Microsoft Automatic Metric documentation](https://learn.microsoft.com/en-us/troubleshoot/windows-server/networking/automatic-metric-for-ipv4-routes).

- Preserve the full snapshot SHA, including both metrics, for integrity verification.
- Add a domain-separated continuity SHA over all networks, local addresses and route interface/prefix/next-hop tuples. Preserve ordering normalization and multiplicity.
- Keep rejection of every equal-or-more-specific competing route regardless of cost, physical-adapter selection, local source binding, fresh pre/post-wave reads, selected-device ARP/MAC confirmation and all address restrictions.
- Reuse only one fixed-script, scan-scoped PowerShell process. Each correlated request executes all original read-only metadata cmdlets again; no cached routes, unsolicited stream, arbitrary commands, elevated service or new dependency.
- Keep the 1024-target, 16-connection, 600ms-connect, 5-second metadata and 45-second discovery limits. Larger/slower supported subnets may still time out; never call truncated results COMPLETE.

The continuity equivalence relies on the existing conservative route validator: all admissible most-specific paths for an accepted target are on-link through the same physical interface. Cost changes alone cannot authorize a new destination, interface or next hop. The full hash must not be replaced with the continuity hash for integrity checks.
