# Desktop-Display-StateLayout-01A Test Guide

本说明用于验收顾客屏 `/desktop/display` 状态驱动布局小步重排。

## 目标

- 空闲态、订单态、KHQR 支付态、完成态拆成稳定独立布局。
- 空闲态不再显示大 KHQR。
- 从空购物车点击第一个商品时，不应闪回欢迎页。
- 不改 PosSession API、不改 `/cashier` 主收银链路、不改 KHQR 回调/查单。

## 测试准备

1. 员工端打开：
   `/cashier?storeCode=ST169E7000`
2. 顾客屏打开：
   `/desktop/display?storeCode=ST169E7000`
3. 确认员工端购物车为空。

## IDLE 空闲广告屏

1. 顾客屏应显示门店欢迎信息和“本周热销”大图。
2. 空闲态不应显示大 KHQR 二维码。
3. 可看到 CASH / KHQR 支持提示。
4. 全屏按钮和语言切换仍可使用。

## ORDER_ACTIVE 金额确认屏

1. 员工端从空购物车点击第一个商品。
2. 顾客屏应直接进入订单态，显示应付金额和商品列表。
3. 不应出现“欢迎页 / 等待页”闪回。
4. 继续添加商品，金额和商品列表应稳定更新。
5. 修改数量时，顾客屏不应明显闪屏或整页重载。

## PAYMENT_KHQR 扫码支付屏

1. 员工端选择 KHQR 收款。
2. 顾客屏应进入扫码支付态。
3. 顾客屏应显示“请扫码付款”、本单金额和更突出的 KHQR 二维码。
4. 不应显示热销轮播或空闲欢迎页。
5. 员工端切回 CASH 后，顾客屏应回到订单金额确认态，并清除本单 KHQR。

## COMPLETED 完成态

1. 员工端完成销售。
2. 顾客屏应显示完成 / 感谢提示。
3. 约 2.5 秒后回到 IDLE 空闲广告屏。
4. 回到空闲态后不应保留旧商品或旧 KHQR。

## 回归检查

1. 在线 CASH 收银不受影响。
2. 在线 KHQR 收银不受影响。
3. 离线 CASH 收银不受影响。
4. PosSession 同步仍可在双浏览器 / 双屏场景下工作。
5. 热销轮播仍正常循环。
6. 全屏按钮仍可进入和退出全屏。

## 通过标准

- `/desktop/display?storeCode=ST169E7000` 正常打开。
- 空闲态不显示大 KHQR。
- 首件商品后直接进入 ORDER_ACTIVE。
- KHQR 收款进入 PAYMENT_KHQR，二维码明显突出。
- 完成销售后进入 COMPLETED 并回到 IDLE。
- 未改数据库、未改 API 结构、未改 `/cashier` 主收银逻辑。
