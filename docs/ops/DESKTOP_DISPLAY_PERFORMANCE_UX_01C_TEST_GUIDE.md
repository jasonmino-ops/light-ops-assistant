# Desktop-Display-Performance-UX-01C 测试指南

本指南用于验证电脑端顾客屏 `/desktop/display` 的加载、回空闲态、热销图片比例和闪屏抖动精修。

## 范围

- 只验证顾客屏体验精修。
- 不改 PosSession API。
- 不改 KHQR 生成、回调或查单。
- 不改 `/cashier` 主收银链路。
- 不涉及数据库或 migration。

## 首屏加载

1. 打开：
   `/desktop/display?storeCode=ST169E7000&lang=zh`
2. 确认页面不会长时间空白。
3. 店名、欢迎框架和右侧支付区域应尽快出现。
4. 热销图片可以渐进加载，但容器尺寸应稳定。

## 热销轮播图片比例

1. 确认空闲态“本周热销”仍每次只显示一张商品。
2. 商品图片应成为主视觉。
3. 商品名、规格、价格在底部轻量显示，不抢图片主体。
4. 多图轮播时，卡片高度不应跳动。

## 闪屏 / 抖动回归

1. 在另一浏览器打开：
   `/cashier?storeCode=ST169E7000`
2. 员工端添加商品。
3. 顾客屏应从空闲态切到订单态，不应整页闪白。
4. 修改数量时，金额应稳定更新。
5. 清空购物车时，顾客屏应回到空闲态。

## 完成销售后回空闲态

1. 员工端完成一笔测试销售。
2. 顾客屏可短暂显示完成态。
3. 约 2.5 秒后应回到欢迎页 / 空闲态。
4. 不应长时间保留旧订单或旧 KHQR。

## KHQR 稳定性

1. 员工端选择 KHQR。
2. 顾客屏应显示本单 KHQR 和金额。
3. 轮播切换不应影响右侧 KHQR 位置。
4. 切回 CASH 后，本单 KHQR 应清除。

## 全屏按钮回归

1. 点击“进入全屏”。
2. 确认可进入全屏。
3. 点击“退出全屏”。
4. 确认可退出全屏。

## 通过标准

- 首屏不长时间空白。
- 完成销售后约 2.5 秒回空闲态。
- 热销商品图片占主要视觉。
- 员工端加商品、改数量时顾客屏不明显闪屏。
- KHQR 位置稳定。
- 全屏按钮正常。
