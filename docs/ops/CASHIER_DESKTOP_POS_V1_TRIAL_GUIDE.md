# Cashier Desktop POS V1 Trial Guide

本文件是 Jason 现场真实门店试跑操作清单。用于验证电脑端 POS Lite 是否可进入小范围商业试跑。

## 1. 试跑前准备

### 设备

推荐方案：

- 员工电脑或一体机 1 台。
- 顾客显示屏电脑或第二块屏幕 1 台。
- 稳定网络。
- 可切换断网 / 恢复网络的测试条件。

### 浏览器

推荐使用 Chrome 或 Edge。

如果已经安装 PWA，建议试跑前确认：

- 旧 PWA 不是缓存旧版本。
- 打开后 URL 中 storeCode 正确。
- 必要时卸载旧 PWA 后重新安装。

### 门店编号

试跑门店示例：

```text
ST169E7000
```

员工端和顾客屏必须使用同一个 storeCode。

## 2. 打开员工端

员工端 URL：

```text
/desktop/pos?storeCode=ST169E7000&lang=zh
```

检查：

- 页面正常打开。
- 不跳 Telegram 绑定页。
- 商品列表可见。
- 左侧“销售记录”可见。
- CASH / KHQR 收款入口可见。

## 3. 打开顾客屏

顾客屏 URL：

```text
/desktop/display?storeCode=ST169E7000
```

检查：

- 门店名称正确。
- 处于空闲态。
- 可见欢迎页 / 热销商品。
- 右上角有“进入全屏”。

## 4. 进入全屏

### 员工端

按当前页面入口或浏览器全屏方式进入。

### 顾客屏

点击右上角“进入全屏”。

退出方式：

- Mac：`Control + Command + F` 或 `Esc`
- Windows：`F11` 或 `Esc`

## 5. 测试在线 CASH

1. 员工端选择 1 个商品。
2. 顾客屏应显示商品和金额。
3. 修改数量，确认顾客屏金额同步。
4. 选择 CASH。
5. 完成销售。
6. 顾客屏应显示完成态，然后回空闲态。
7. 打开销售记录，确认出现 CASH 记录。

通过标准：

- 员工端能完成收银。
- 顾客屏不残留旧单。
- records 能看到记录。

## 6. 测试在线 KHQR

1. 员工端选择商品。
2. 选择 KHQR。
3. 顾客屏应显示本单金额和 KHQR 二维码。
4. 顾客扫码或模拟扫码。
5. 员工人工确认已收款。
6. 完成销售。
7. 打开销售记录，确认出现 KHQR 记录。

注意：

- 当前 V1 不做自动到账确认。
- 当前 V1 不做 KHQR 回调自动完成。
- 员工必须人工确认收款。

## 7. 测试顾客屏同步

在员工端依次操作：

1. 加商品。
2. 改数量。
3. 删除商品。
4. 清空购物车。
5. 选择 KHQR。
6. 切回 CASH。
7. 完成销售。

顾客屏必须确认：

- 商品和金额同步。
- KHQR 状态正确显示。
- 切回 CASH 后二维码清除。
- 清空 / 完成销售后无旧单残留。
- 首件商品进入订单态可接受，当前约 1.3 秒，不承诺本地原生 POS 级实时。

## 8. 测试离线 CASH

### 联网缓存

1. 联网打开员工端。
2. 确认商品加载正常。
3. 确认页面显示商品缓存状态。

### 断网收银

1. 断开网络。
2. 页面应进入离线状态。
3. 只允许 CASH。
4. 选择缓存商品。
5. 完成离线 CASH 收银。
6. 页面显示待同步离线订单数量增加。

注意：

- 离线状态不支持 KHQR。
- 离线状态不支持会员余额支付。
- 离线订单不会立刻进入 records。

### 恢复网络同步

1. 恢复网络。
2. 点击“同步离线订单”。
3. 同步成功后本地订单标记为 SYNCED。
4. records 显示“离线补同步”标签。

## 9. 查看销售记录

1. 从 `/desktop/pos` 左侧点击“销售记录”。
2. 确认 URL 带 `storeCode=ST169E7000&from=desktop`。
3. 确认不跳 Telegram 绑定页。
4. 确认只显示当前门店记录。
5. 确认 CASH / KHQR / 离线补同步显示正常。
6. 点击“返回收银台”回到 `/desktop/pos`。

## 10. 查看 dashboard

1. 打开 dashboard。
2. 查看今日销售。
3. 查看是否有离线补同步提示。
4. 确认页面不白屏、不报错。

当前 dashboard 不重写主统计口径；离线补同步提示为轻提示。

## 11. 发现问题如何记录

每个问题至少记录：

- 时间。
- 设备。
- 页面 URL。
- 操作步骤。
- 期望结果。
- 实际结果。
- 截图或视频。
- 是否影响继续收银。
- 是否可复现。

建议问题分类：

- P0：无法收银 / 丢单 / 串店 / 金额错误。
- P1：顾客屏明显不同步 / records 对账异常 / 离线订单无法同步。
- P2：页面布局、按钮、提示、操作体验问题。
- P3：文案、视觉细节、非阻塞优化。

## 12. 哪些情况先停止试跑

出现以下情况应先停止试跑：

1. records 显示其他门店数据。
2. CASH / KHQR 金额与顾客屏金额不一致。
3. 完成销售后 records 没有记录。
4. 离线订单恢复网络后无法同步且无法保留本地记录。
5. 顾客屏长期显示旧订单或旧二维码，影响顾客付款。
6. 连续出现白屏或无法加载商品。
7. 店员无法理解当前操作路径，导致真实收银风险。

## 13. 试跑通过标准

建议 30 分钟现场试跑：

- 连续 20 单在线 CASH / KHQR 不出错。
- 断网 CASH 3 单可保存。
- 恢复网络后 3 单可同步。
- records 对账正确。
- 顾客屏不串店、不残留旧单。
- 双屏全屏模式稳定。
- 店员无需理解 Telegram / PosSession / storeCode 技术细节即可使用。

## 14. 当前不测内容

本次 POS V1 试跑不测试：

- 自动到账确认。
- KHQR 自动回调完成。
- 完整退款。
- 本地 USB 打印。
- 日结 / 交班。
- Windows exe。
- 本地桌面客户端。
- AI 营销。
- 完整会员营销。
