# Display-State-Alignment-Fix-01-02 测试说明

本说明用于验证电脑端 POS 选择收款方式阶段的顾客屏状态不再被旧 CASH/DRAFT 同步覆盖，并确认返回本单确认时不再停留 KHQR 支付态。

## 范围

- 只验证 `/desktop/pos` 与 `/desktop/display` 的状态同步。
- 不验证新的支付能力。
- 不验证退款、dashboard、records 统计或数据库结构。

## 测试准备

1. 打开员工端：
   `/desktop/pos?storeCode=ST169E7000&lang=zh`
2. 打开顾客屏：
   `/desktop/display?storeCode=ST169E7000&lang=zh`
3. 确认两边使用同一个 `storeCode=ST169E7000`。
4. 确认员工端购物车为空。

## 路径 1：进入选择收款方式后保持 KHQR

1. 在员工端添加商品。
2. 点击「确认本单」。
3. 点击「确认本单，选择收款方式」。
4. 等待 300ms 以上。

预期结果：

- 顾客屏保持本单 KHQR / 待支付状态。
- 顾客屏不回退到现金。
- 顾客屏不回退到普通订单态。
- `GET /api/pos/session/current` 返回的 `paymentMethod` 应保持 `KHQR`，状态应保持待支付语义。

## 路径 2：KHQR 后切 CASH 不出现混合状态

1. 进入选择收款方式阶段。
2. 点击「扫码收款 KHQR」，确认大二维码弹窗出现。
3. 点击「现金收款 CASH」。
4. 等待 300ms 以上。

预期结果：

- 大二维码弹窗关闭。
- 不出现「底层现金 + KHQR 大弹窗」混合状态。
- 状态不来回跳。
- 最终点击「确认现金已收款，完成销售」后，销售记录记为 CASH。

## 路径 3：返回本单确认

1. 进入选择收款方式阶段。
2. 顾客屏显示本单 KHQR。
3. 点击「返回本单确认」。

预期结果：

- 顾客屏回到普通订单 / 商品金额展示。
- 不显示 KHQR 大弹窗。
- 不保持 PAYMENT_KHQR。
- 商品和金额不丢。

## 路径 4：返回修改商品

1. 进入选择收款方式阶段。
2. 点击「返回修改商品」。
3. 修改商品或数量。
4. 再次进入选择收款方式。

预期结果：

- 返回后顾客屏不保留旧 KHQR。
- 再次进入选择收款方式后显示新金额 KHQR。
- 不出现旧金额残留。

## 路径 5：完成销售

分别验证：

- CASH 完成销售后，records 记录为 CASH。
- KHQR 完成销售后，records 记录为 KHQR。
- 顾客屏进入感谢页。
- 员工端购物车清空。

## 路径 6：非 desktop 回归

1. 打开 `/cashier?storeCode=ST169E7000&lang=zh`。
2. 确认原 CASH / KHQR 流程不变。
3. 确认原完成销售流程不变。
4. 打开 `/sale`，确认页面不受影响。
