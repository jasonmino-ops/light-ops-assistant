# 门店 RC5 安装、双角色配置及出纸验收单

使用范围为内部实机验收。现场记录由能看到两台打印机的人填写。本单当前没有实物验收回执。

| 项目 | V727 本次绑定 | 下一家门店须自行取得 |
|---|---|---|
| 安装 | Windows x64，Desktop 0.3.0-rc.5，Provider 0.1.0，Add-on 0.1.0-commercial-rc.14；安装包 SHA-256 `a5747147ee43f515d3ada2f347b89efbc3bb1ae75fec67662c7f3a8bd0f91a61` | 已批准用途的包、哈希、固定收银用户；以 current-user 正常非提权安装 |
| 商户身份 | ST04C05602，设备 `cmwsu4zip001s08l4a3464hkt` | 使用该店自己的 PIN 激活、设备授权、POS Session 与 Print Child 加密交接 |
| 前台 | 非共享队列 `E-Shop FRONT USB003`，端口 USB003，USB 0483:5743，序列号 1C7D118C0000 | FRONT 在 USB/TCP 中选一种。USB 使用签名驱动、实体序列和唯一队列匹配；Windows 端口编号只作为当前位置 |
| 后厨 | NP330 `192.168.18.229:9100`，MAC `00-9D-85-8E-7E-E1` | 验证本店实体设备、IP、MAC 和端口；KITCHEN 仅 TCP。餐饮由有权限的人确认厨房单，非餐饮默认关闭 |
| 运行权 | 旧 Owner epoch 1、版本 4744、七票待隔离 | 核对本店 Owner、租约、批次、HELD、未回报任务。新开门店走正常初始授权；仅 ST04 适用本案七票处置 |

1. 核对源码及安装包清单、现场主机、设备身份和实际 Windows 用户。启动后先确认收银台可用；进入与退出设置，读回同一 POS Session，核对 Print Child 和门店。保留双方的配置前像。
2. 先完成本店 Owner 准入。ST04 须读回七票的逐票前像、EXPIRED/物理 UNKNOWN 后像、空领取及空执行等证据，再由门店 OWNER 正常交接。核对新 Owner 设备、epoch、租约、Fence 和切换时刻；激活前检查没有待释放的旧任务和待回报记录。授权或读回不符立即停止。
3. 在当前 RC5 受认证的配置入口或既有本地导入流程提交本店两个角色。V727 使用本机已保全的 rev1 配置输入，SHA-256 `f2ed5d09de40ba8e33fde1372b0a2cdbb20e169ce5e71c846ca66d5e5de402f3`。从运行时读回 store、device、revision、两个目标及权限状态。正常重开再读回；继续保留原 USB001 队列及其历史。厨房开关须另有本店 OWNER 的有效权限和业务确认。
4. 两人在现场或一人能同时核对两台实体设备时，生成两个不同的新诊断标识。先 FRONT 一张，由观察人抄录票上标识、角色、出纸台和时间；确认准确后再 KITCHEN 一张。每个动作只发一次。
5. 用获准的全新餐饮测试单走正常收银入口；预期同一订单恰好生成 FRONT 和 KITCHEN 两个角色任务，各出一张。记录测试标识、订单 ID、两个 job ID、幂等键摘要、Owner/epoch、Ledger/Outbox 执行次数、云端终态与两台实际纸票。四张预期纸票逐一对应。跨角色输出、缺票、多票、回报不明或纸票不可见时停止并保留凭证；对不明效果只读核验。
6. 只有四张实物与四个新效果逐一对应、无额外领取/打印、七个旧效果未进入调度、收银返回正常，方可签署本店 FIELD。下一家商户的商业交付还须有适用的签名、正式发布和商户交付批准。
